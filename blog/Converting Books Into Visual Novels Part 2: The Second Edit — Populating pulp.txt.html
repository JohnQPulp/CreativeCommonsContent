This process will document the steps involved with second edit of pulp.txt, the one in which we fully mostly populate its metadata.

The Second Edit's Goals

In the first edit, we had the LLM generate us up some initial n (name definition) tags, s (speaker attribution) tags, e (emotion labeling) tags, and line breaks. The LLM tends to do a decent job at labeling those bits of metadata, but it certainly isn't perfect, so one of the goals of this second edit will be to review and edit those tags as-needed.

At the same time, we also need to populate most of rest of the missing metadata tags, as all these will also be involved in determining the set of images we'll actually need. These being:

  • The background-determining tag — the b tag — where we'll have to figure what background we want active for each slide of the VN.
  • The tags that determine which all base sprites we'll need — the a age-determining tags (e.g., a:char=old if a character ages over the course of the text) and the x eXtra-attribute tags (e.g., x:char=hat if a character needs to wear a hat in a scene).
  • The tags that determine when we'll need to have sprites to show, which on top of the already mentioned s speaker tags also includes: the t thinker tags (for close-mouthed sprites instead of open-mouthed ones), the g frame narrative tags, which determine what depth layer within dialogue the active speaker is determined from, and the c on-screen character positioning tags.
  • The sprite expression-determining tags, which on top of the already mentioned e emotion tag also includes the i expression index tag, for controlling which of the potentially multiple variations on the same expression is shown at a given time.
  • The object-determining tag — the o tag — though only when on-screen objects are used, which is becoming less common.
  • And then lastly, the f filter and m modifier tags, which are both a little different and special in both their usages and effects: neither actually determines the set of required images themselves (usually), but both heavily influence how the other tags need be set, especially the background tag, and therefore it makes since to include setting these as part of the second edit. (This will be elaborated on in much more detail further below.)

Both of these subgoals — editing the existing metadata tags and adding in the set of new metadata tags — essentially force us to do a full re-read of the book. And we can't really skim-read either, since a book's visual-determining descriptors can hide anywhere in a text.

Of course, having already read the book once helps a lot with knowing where special editing attention will be needed to get the visuals right. But even so, the second edit is still necessarily a much closer and more involved and longer one than the first. We have to develop a mental model of how all these visuals will fit and flow together, prior to actually being able to see any of them.

The results of the second edit won't be perfect then. But the goal isn't perfection, but rather to set ourselves up for a smooth process in the subsequent sprite-generation step, background-generation step, and final visual-editing step.

Some reworking and rethinking will be required in those steps, since actually being able to see the visuals will change how we want to structure some of the metadata to flow better and be more accurate, but the goal of the second edit is to develop a close-enough approximation of what the final metadata should need to look like, that we can avoid major re-editing in those later steps.

Overview

Since the second edit if a full re-read, it involves going sequentially back through the entire text, editing or editing-in any of the previously mentioned aspects of the metadata at any point in the text. From an editing-process perspective, all of the metadata needs to be considered all at once.

But from an explanatory perspective, that would be impossible to follow. So instead, we'll break up the different metadata-editing aspects into subcategories, explaining the specific considerations involved in each conceptual grouping.

Just keep in mind, though, that the order of these sections for the rest of the post isn't the order the edits should be done in, but rather just a way to mentally compartmentalize all the different potential edits that need to be happening throughout the course of the full sequential re-read.
